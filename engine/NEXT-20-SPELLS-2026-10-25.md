## Engine changes in this batch

- `EMMSpell.kt` supports optional caster tile `requiredBaseTerrain` and `requiredTerrainFeature` preconditions.
- `EmmSpellEngine.kt` checks those tile preconditions before casting.
- `Slowed` is now a defined movement debuff; Haste removes it. Previously the Haste reference was unresolved.
- Spellstaff persists as a unit status and is consumed after one successful additional cast, including if ordinary casting exhausted movement; the new behavior must be verified against unit action UI visibility, turn order and save/load.
- The all-355 native registry validator now accepts unit-granted actions as well as promotion-granted actions.
- The existing vanilla proxies were removed from the corresponding sphere or unit unique lists where migrated to native actions.

## Important readiness distinction

**Registered is not gameplay verified.** Ten definitions have grants on already-defined player units or sphere promotions. The five Esus, two divine, and one potion permission promotions are experimental: those eight currently lack a legitimate game progression path. The remaining staff/resurrection entries use existing spheres but have partially simulated behavior. The source's EMM Python handlers and several essential subsystems are not yet ported, and the existing status proxies are not source-exact.

**Do not advertise all 20 as faithful or fully playable.** This batch brings the native registry to 60/355, leaves 295 source actions without native definitions, and does not replace the need for full Android testing.

## 2026-10-25 mechanics-hardening checkpoint

A Spellstaff extra-cast loop was found in native cast gating. If a unit had a stored Spellstaff charge, it could attempt to use that extra cast on `Enchant Spellstaff` and refill itself. The engine now explicitly rejects the staff-enchant action while already charged and rejects it during the extra cast. A static guard regression assertion was added. Existing one-extra-cast consumption remains in place.

**Outstanding source fidelity:** the pinned EMM source XML/Python could not be retrieved in this work session. Therefore no speculative ownership transfer, teleport-to-capital or fallen-hero state-restoration mechanism was added. Domination, Escape and Resurrection still use nonfaithful proxies as explicitly documented above. Building a source-faithful port requires the pinned XML and Python handlers plus the relevant Unciv Kotlin ownership, movement and unit-serialization APIs; none of those mechanisms has been verified yet.

The 60-item native registry count remains unchanged. No Android compile or in-game result is claimed for this checkpoint.
